# Security Evidence Map

This map connects the contract's security claims to executable evidence. Start
from either side:

- **Prose to tests:** the invariant and practical-threat tables point from each
  whitepaper claim to the tests that enforce it.
- **Tests to prose:** the attack-log table points from every named attack
  regression and intentional control to its owning whitepaper claim or
  limitation.

Test identifiers below are verbatim and grep-verifiable. A renamed or removed
test therefore leaves a visible dead reference. In Aiken, a test declared with
`fail` passes only when the evaluated attack is rejected. A normal passing test
is used where the claim needs a legal boundary case or an intentional control.

Run the complete evidence set from this directory:

```sh
pnpm verify
```

The canonical security prose is the whitepaper's [Security
Analysis](../../whitepaper/whitepaper.pdf), *Formal Model*, *Threats mitigated
in practice*, and *Limitations and Trust Assumptions*. Section names, not
numbers, are used here because numbering may change.
