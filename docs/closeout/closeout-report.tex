\section{Deliverables}

Epora is a permission-based smart wallet on Cardano. It lets users plan recovery after inactivity, share control, and give other people limited spending rights. A normal wallet holds the signing keys. The smart wallet holds funds and checks whether each action meets its configured rules.

The project delivered the contract system, reference application, public API, whitepaper, and developer documentation. The application runs on \href{https://mainnet.epora.io}{mainnet} as an unaudited beta, with a \href{https://epora.io}{Preprod deployment} for testing. The project's own code and documents are public under the \repo{LICENSE}{MIT license}.

\section{Usage}

\subsection*{Who the wallet is for}
Owners can configure a recovery plan if they become inactive. Families can name beneficiaries and assign recovery shares. Shared treasuries can require co-signatures or give users daily allowances. Developers can use the API to build wallet integrations.

A user connects a signing wallet, creates and funds a smart wallet, then sets its permissions. Each action follows a review and signature flow. A co-signed action collects the required approval weight. When the proof-of-life period expires, eligible beneficiaries can use the configured recovery path. These are intended uses; the activity snapshot below measures the deployed prototype.

\section{Impact}

The project turns the proposed dead-man-switch and permission model into working contracts, an application, and an API. Users can combine recovery, shared control, and spending limits in one smart wallet. Other developers can inspect the implementation and build on the same public specification.

\subsection*{Project outcomes}

\toprule
\hd{Original objective} & \hd{Result and evidence} \\
\midrule
Recover after inactivity & A configurable proof-of-life deadline and beneficiary rules. The mainnet settings transaction added a beneficiary and a 30-day period; a later operator spend refreshed the deadline. See \repo{docs/closeout/mainnet-evidence.md}{transaction evidence}. \\
\addlinespace
Share control and limit spending & Weighted multisignature and per-day allowances are implemented in the contract and reference application. The \repo{whitepaper/whitepaper.pdf}{whitepaper} and \repo{code/smart-contract/INTERACTIONS.md}{transition map} explain the authorization rules. \\

\subsection*{Testing and measured results}
The \repo{docs/mainnet-beta-release.md}{25 September release record} records \texttt{750 passed, 0 failed} with Aiken v1.1.23: 713 unit tests and 37 property tests. The property run used 10,000 cases per property. The rebuilt blueprint matched the committed artifact. The linked security tests cover the stated invariants and abuse cases; the beta has not had an external audit.

Mainnet transactions establish successful wallet creation, funding, settings changes, and operator spending. The Demo wallet creation cost 0.447194 ADA. Its operator spend with automatic proof-of-life refresh cost 0.912502 ADA. These are measured examples, not a fee bound for all configurations. The two-wallet inventory is not a measure of independent adoption.

\subsection*{Lessons from delivery}
\textbf{Script size affected the deployment design.} The state script is 14,469 bytes. A reference script lets transactions use it without including the full script each time. The \repo{docs/mainnet-beta-release.md}{release record} documents its hash and size, and the mainnet evidence records the deployed reference.

\textbf{Shared control needs a usable coordination flow.} A tester could not tell a co-signer to complete registration. The resulting changes added an invitation link and a per-co-signer sign-in status. The \repo{docs/testnet-feedback.md}{feedback register} links the report to the fixes. Permissions need both enforceable rules and a clear way for people to complete the required steps.

\section{Sustainability}

\subsection*{Maintenance and operating costs}
Epora continues as an open-source project. The beta is maintained, and public issues are reviewed for further fixes. The public repository and documentation allow other developers to inspect and contribute to the work.

No revenue is currently generated. Server and other operating costs are covered by received Catalyst funds. Future funding or paid services will depend on adoption and partner agreements; there is no committed recurring revenue model yet.

\subsection*{Next steps}
Continue the beta with its unaudited-code notice and address feedback through the public issue tracker. Follow up with wallet teams and explore a smart-wallet CIP. The proposed standard could define how wallets discover smart wallets, display their rules and balances, and build permitted actions. A standard could also support shared maintenance across implementations. After community feedback on the proposed CIP, the need for an external audit will be assessed against that feedback and the CIP implementation. If an audit is needed, a separate funding round is planned to cover its cost. Existing Catalyst funds and personal funds are not intended to fund the audit.

WalletConnect signing and device testing, plus wallet-signed terms acceptance, are deferred. The beta currently uses an acknowledgement flow. The \repo{tasks/milestone-5-mainnet-closeout.md}{engineering checklist} also retains operational follow-up: backup and reindex drills, monitoring verification, and wider fee and multi-asset testing. Those checks are separate from the delivered prototype and measured transactions in this report.
