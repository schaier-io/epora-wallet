\section{Deliverables}

Epora implements a permission-based smart wallet on Cardano. A normal wallet signs actions and pays transaction fees. The smart wallet holds funds and enforces its configured permissions. The public repository contains the Aiken contracts, web application, API, whitepaper, and tests. The project's own code uses the MIT license.

\subsection*{A. Output: Mainnet beta prototype}
\textbf{Delivered.} The mainnet beta is online. Confirmed transactions show wallet creation, funding, an operator spend, and a settings update. The settings update added a beneficiary and a 30-day proof-of-life period. A later operator spend advanced that deadline. This is evidence of automatic renewal during an operator action, not the separate manual renewal path.

\textbf{Acceptance criteria.} A working mainnet prototype. The approved milestone specifies a beta because the code has not been externally audited.

\textbf{Verified evidence.} \href{https://mainnet.epora.io}{Mainnet application}; \href{https://mainnet.epora.io/api/health}{health endpoint}; \repo{docs/closeout/mainnet-evidence.md}{transaction hashes, balances, and measured fees}. At 01:30 UTC, health returned HTTP 200 with database and indexer \texttt{up}. The reference-script endpoint returned \texttt{ready}. Section 2 gives the on-chain evidence.

\section{Impact}

The project gives Cardano users a contract-based way to configure shared control, spending permissions, and recovery after inactivity. A normal wallet keeps the signing keys. The smart wallet checks which action those keys may perform. A lost-key or inheritance plan can therefore include another authorized signer instead of relying only on one seed backup.

\subsection*{Testing and engineering results}
\textbf{Reported validation record.} The \repo{docs/mainnet-beta-release.md}{release record} gives the exact output \texttt{total: 750, passed: 750, failed: 0} for Aiken v1.1.23. It records 713 unit tests, 37 property tests, and a run with 10,000 cases per property. The blueprint was rebuilt and compared with the committed artifact. These are recorded results from 25 September, not a new test run for this report. The \repo{code/smart-contract/SECURITY.md}{security evidence map} connects stated threats to executable tests. None of this is an external audit.

\textbf{Design result.} One contract configuration combines the supported permissions. The state validator checks the declared action and state change. The wallet validator limits how funds move. This separates permission rules from payment enforcement and supports review through the published transition map.

\textbf{Measured mainnet result.} The prototype has completed real mainnet transactions. The measured Demo wallet creation fee was 0.447194 ADA. Its operator spend with automatic liveness refresh cost 0.912502 ADA. These measurements establish the observed costs only. They do not establish savings against other wallets or a fee bound for every configuration.

\textbf{Timeline.} The original plan covered seven months, ending in October 2024. Admin signoff for milestones 1 to 3 occurred in July through September 2026. The reported completion date is 26 September 2026. The approved project budget remains 100,000 ADA. The portal showed 59,000 ADA distributed at this check, so the report does not claim that the full budget has been received.

\section{Sustainability}\label{sec:next}

\textbf{Ongoing project.} Epora continues as an open-source project. Sandro Schaier and the project team plan to maintain the beta, triage public issues, and fix defects. The public repository and documentation let other developers inspect and contribute to the work.

\textbf{Operating funds, reported by the project manager.} Received Catalyst funds pay for servers and other operating costs. No fixed operating runway or committed recurring revenue is established in this report. Future funding or revenue depends on adoption and partner agreements.

\textbf{Planned roadmap.} Continue the beta with its permanent unaudited-code notice. Follow up with wallet teams and explore a smart-wallet CIP. The proposed standard could describe how wallets find smart wallets, display their rules and balances, and build permitted actions. Shared maintenance with wallet teams is a possible longer-term outcome, not an agreed commitment. External audit funding and scope remain future decisions.

\subsection*{Open checks and deferred work}
\textbf{Verified record status.} The mainnet evidence closes the earlier gap around observed transactions and some actual fees. It does not establish the following operational checks:

\begin{itemize}[leftmargin=1.2em]
\item A timed backup restore, snapshot retention verification, or timed reindex from an empty database.
\item Production database isolation and a deliberate monitoring-alert drill.
\item Mainnet measurements for all remaining action types, multi-asset minimum ADA, and fragmented-wallet consolidation.
\end{itemize}

These remain in the \repo{tasks/milestone-5-mainnet-closeout.md}{engineering checklist}. The approved milestone acceptance criteria ask for a mainnet prototype, categorized feedback, wallet communication, the report, and the video. The checklist has broader operational work and does not itself amend those criteria.

\textbf{Deferred, reported by the project manager.} WalletConnect signing/device testing and wallet-signed terms acceptance remain deferred. The shipped beta acknowledgement is not wallet-signed terms acceptance. VESPR retesting, the external API guide review, and an API-built confirmed transaction are recorded as complete on the project manager's confirmation. The chain evidence here does not independently identify those tests or their client software.
